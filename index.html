Especificación SDD & Clean Architecture

Dominio, Entidades y Reglas de Negocio Formales
Reglas de Negocio Validadas en Tiempo Real:
  • RN-01: No se puede crear ni actualizar una tarea con fecha de vencimiento en el pasado.
  • RN-02: Una tarea en estado COMPLETADA o CANCELADA es terminal e inmutable; no puede cambiar a PENDIENTE ni EN_PROCESO.
  • RN-03: No se permite agendar un compromiso que se traslape con otro compromiso en estado PROGRAMADO o CONFIRMADO del mismo creador: (NuevoInicio < ExistenteFin) && (NuevoFin > ExistenteInicio). Extremos contiguos están explícitamente permitidos.
  • RN-04: Duración mínima garantizada de al menos 15 minutos (fechaFin - fechaInicio >= 15 min).
  • RN-05: Todos los correos de participantes deben cumplir con la validación de formato RFC 5322.
Capas de Seguridad Implementadas en Node.js:
  • Capa 1: Helmet-compliant HTTP Security Headers (Content-Security-Policy, HSTS, NoSniff, X-Frame-Options).
  • Capa 2: Rate Limiter con sliding window por IP (150 req/min general, 40 req/min mutaciones con código 429 Retry-After).
  • Capa 3: Input Sanitizer recursivo neutralizando XSS, scripts y atributos inline maliciosos.
  • Capa 4: Autenticación Bearer Token y RBAC por operador (`X-Orbital-Token`).
  • Capa 5: Guards de Dominio estrictos (RN-01 a RN-05).
  • Capa 6: Audit Logger con registro inmutable de transacciones e incidentes.
